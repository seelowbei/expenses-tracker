**Staging sign-off (November 19, 2026):** the user verified the deployed staging app and reported every check passed: the deploy and migration 0003 with older rows; two-account isolation and private categories; upload → review → ledger with both review paths, exact money, time ordering, pagination and deletion; unsaved-changes flows (dirty close, account switch, expired session); two tabs and a lost save response; missing or disconnected Drive originals; route CPU within the 10 ms budget; and M3 upload, polling and retry.

## Automated checks

- All 288 Workerd tests passed across 32 test files. Worker, web and both infrastructure type checks passed. The SPA production build and Worker dry-run bundle passed.
- The delete tests exercised the real route with synthetic D1 records. They verified 204 on success, identical 404 responses for inaccessible and missing entries, version and receipt-state conflicts, and session and Origin checks. Malformed and oversized bodies were rejected.
- Competing deletes produced one winner. A competing edit or receipt claim at the batch boundary blocked the delete. A forced failure while resolving the receipt rolled back ledger removal.
- Deletion retained the original link, hash, extraction and usage evidence. Ledger totals dropped only the deleted entry's currency contribution. A stale missing-entry review, delayed queue delivery and duplicate upload could not recreate the entry. Test fakes recorded zero Drive or AI calls from this sequence.
- The receipt list derives its association from the session user's ledger. Cache tests verified that a stale response cannot restore a deleted entry's pending badge or publish private data after sign-out.

## Chrome checks

- The built SPA was exercised with synthetic API responses. In the inbox editor, Escape returned focus to the delete button and retained an unsaved merchant change. A simulated stale version showed the latest server values while retaining the draft. After adopting that version, a new confirmation submitted the latest timestamp.
- At 320 px both confirmation buttons fit within the viewport. Successful deletion closed the editor, moved focus to the inbox heading, cleared the pending receipt and updated the totals without a page reload.
- From the ledger, an uncertain delete response followed by a 404 on the state check closed the editor and refreshed the ledger without a second delete request. The retained receipt displayed “No ledger entry.”
- A missing-entry draft offered save without a delete action. Saving it created an expense and updated the SGD total. Deleting that expense from the ledger restored the previous SGD total, preserved the JPY total and displayed “No ledger entry.” The simulated missing Drive original did not block deletion.
