This note was written after the merge from the evidence recorded under Task 10 of the [retired checklist](https://github.com/seelowbei/expenses-tracker/blob/4dcf258/tasks/todo.md#task-10--add-a-custom-category).

## What changed

- `POST /api/categories` creates a private category from a bounded display name. The server generates the ID and slug, with a hash-based fallback when a name yields no ASCII slug. The user association comes from the session only.
- A name or slug that matches a visible category, including system defaults, returns `409 category_exists`. The conflict check runs inside the insert, so concurrent requests cannot create duplicates.
- The review editor creates and selects the new category without discarding other edits. The category reaches later extractions through the existing category lookup; other users cannot see or select it.

No schema migration, dependency, binding or extraction-prompt changes.
