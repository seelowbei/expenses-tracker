# M4.1 — Read-only ledger verification

November 17, 2026. Branch: `codex/m4-ledger-browsing`. Scope: the first PR in [the M4 plan](./M4%20plan.md). Local implementation and verification are complete; PR review and staging verification remain.

**Staging sign-off (November 19, 2026):** the user verified the deployed staging app and reported every check passed: the deploy and migration 0003 with older rows; two-account isolation and private categories; upload → review → ledger with both review paths, exact money, time ordering, pagination and deletion; unsaved-changes flows (dirty close, account switch, expired session); two tabs and a lost save response; missing or disconnected Drive originals; route CPU within the 10 ms budget; and M3 upload, polling and retry.

## Delivered

- Authenticated category listing, paginated ledger listing and entry detail. Filters validate real dates, category ownership, bounded ranges/limits and cursor/filter consistency.
- SQL totals over the full filtered range, separately by category, month and currency, including counts of provisional entries. The UI combines months into a grand total per currency and one subtotal per category, retaining review notices. Exact integer aggregation and formatting cover zero-, two- and three-decimal currencies, including combined sums above the safe-number boundary.
- Month navigation, custom date ranges, category selection, grouped entries, expandable read-only details, empty/error states and original receipt links when present.
- Receipt completion refreshes ledger queries. Account-specific query keys and clearing on logout/session expiry prevent stale account data being reused. In-flight profile requests are cancelled during sign-out.

No migration, dependency, binding, AI prompt or extraction changes. Editing, explicit review confirmation, missing-entry recovery, category creation and deletion remain in later PRs.
